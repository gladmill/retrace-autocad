# Evidence: pictures for the sign-off sheet

`steps.xlsx` is a sign-off sheet (`recording-format.md`). Its Evidence column (I) is where a tester shows what they saw. Retrace fills it in two ways. Neither needs a macro-enabled workbook, and neither changes `steps.xlsx`: both write a **new** workbook beside it, `steps-evidence_<yyyyMMdd-HHmmss>.xlsx` (a second run makes a second file, never overwrites the first).

## A person walks the test: the Evidence window (`RETRACEEVIDENCE`)

Open it from the Open test window (Evidence (camera)) or type `RETRACEEVIDENCE`. Nothing else in Retrace lists the steps of a test for a person to walk (the Guide palette shows the guide's pages, the replay window only shows steps during a replay), so this window is that list.

- The drop-down chooses the test (newest first). The list is the rows of its sign-off sheet (`1`, `1.1`, `2` ...), the current one highlighted; Previous step / Next step move it.
- **Camera** (the button, or `Ctrl+Shift+F12`): every window of Retrace's own that is open (the Evidence window, Open test ...) and a floating Guide palette are hidden (a docked Guide palette is part of AutoCAD's layout and stays), AutoCAD's window is brought to the front, the picture is taken (AutoCAD's window on its monitor's work area, so palettes and dialogs of AutoCAD are in it and the task bar and Retrace's windows are not, scaled to at most 1280 px on the long side), and the windows come back without taking the keyboard focus from AutoCAD: a tester in the middle of a command keeps typing into it. The hotkey is handled only while the Evidence window is open and the key reaches AutoCAD (AutoCAD's own message loop; a key pressed in another program is that program's, and a modal dialog that runs its own loop may not see it: use the button). There is no setting for it: it is not an AutoCAD shortcut. If your checkpoint shortcut (setting `checkpointKey`) is the same chord, the checkpoint wins and the window says so. While recording, the chord is not counted as your input. The Open test button for Evidence closes Open test first.
- Several pictures per step are fine. Retake takes another picture and removes the step's last one only once the new one is on disk; Delete picture removes the picked one. A removed picture is moved to `evidence\removed\`, not deleted.
- Pictures are files: `<test folder>\evidence\step-<row>_<yyyyMMdd-HHmmss-fff>.png` (`step-2.1_20261117-101530-042.png`).
- Tester, Date and, per step, Result and Notes are the tester's to fill in the window (kept per test while the window is open, so switching tests and back loses nothing; Refresh reads the list of tests again). A step's Result is written only when set to Pass, Fail or Blocked; otherwise it stays "Not run" for Excel. Closing the window forgets them (the pictures stay on disk). A picture belongs to a step by its number: when steps.md has changed since the first picture of the test was taken (the test was recorded again into the same folder, steps.md was edited) the window says so in red.
- **Write workbook** writes the new workbook. Each step's pictures sit in the Evidence cell of its row with the sheet's own rule (420 px wide, at most 380 px high, 4 px inset, aspect kept, never enlarged), stacked top to bottom with 4 px between; the row grows to hold them (at most 60 pictures of one step go into the workbook; a note says how many stay in the folder). Excel does not allow a row above 409 pt, so when a stack is taller its pictures all shrink by the same factor, down to half size; beyond that the rest go to the next column (`Evidence 2`, `Evidence 3` ...) in the same row. Tester and Date go in their cells, Result and Notes where set, and the Overall result and counts follow the Result column as in steps.xlsx. Retrace's own picture column is unchanged.
- The how-to note in I3 of steps.xlsx is written for the tester and does not name the product or its camera or commands (documents a tester opens never do): "Evidence: paste a picture of what you saw: Win+Shift+S, click the cell, Ctrl+V." The camera is for whoever runs the Evidence window; a pasted picture does not size itself, which is why the camera is the easier way.

## Retrace replays the test: evidence from a replay

Off by default. Two ways to ask for it:

- the Open test window's **Run with evidence** button (same as Run this test, no verdict box);
- `-RETRACEEVIDENCE` on the command line (scripts): asks for the test (a name, a test folder, a path to its `recording.jsonl`, or `last`).

The replay is the one RETRACERUN does (new drawing, dialogs filled in). After every step has run and AutoCAD has settled (700 ms, then AutoCAD must have been idle since, at most 3 s more; then every window of Retrace's own and a floating Guide palette are hidden for 450 ms and shown again in the same call) a picture of AutoCAD's window is taken. (Retrace's windows are hidden for each picture, including the replay window; the "Step n/m" text at the right end of AutoCAD's status bar in those pictures is the AcadStatus add-in's status pane, part of AutoCAD's window, not Retrace's replay window.) When the test ends the workbook is written in the background and its path printed on the command line:

- **Evidence**: each row of the sheet gets the picture of the screen right after its own action, on that row, never a later state on an earlier row. The replay takes pictures at three moments: a dialog the command opened is on the screen (not filled in yet; AutoCAD's window with the dialog in front), the dialog is filled in (just before the button that closes it is pressed, the same moment the Tdoc pictures it), and a step has run and AutoCAD has settled (for a command with dialogs: after the command ended). So, for a click that starts a command which opens a dialog and then asks for a point and a rotation:
  - the click's row (`1`): AutoCAD with the dialog open (taken half a second after a dialog window is on the screen, so it has been drawn; a command that goes modal with no dialog window gets no such picture and a note);
  - the dialog's row (`1.1`): the dialog as filled in, before OK. A dialog smaller than about half of AutoCAD's window in both directions is pictured ALONE at its own size, so the values can be read in the sheet's cell (the click's row keeps the whole window for context); a larger one is the whole window. A dialog partly off the screen is first moved onto it (as the Tdoc does), and one that lies outside AutoCAD's window is pictured with the window widened to hold it;
  - the prompts after the dialog (`1.2`, `1.3`): the answers are typed in one go, so the last of those rows gets the screen after the command ended (the drawing with the inserted object) and the earlier ones say where their picture is;
  - prompts between two dialogs: the screen when the second dialog has opened; a command with no dialog: the end picture is on its last row only;
  - a palette row, a status bar row, an intermediate palette click and a checkpoint row: the screen after that step (a click whose dialog the recording made a step of its own: that dialog as it opened, which is the screen right after the click).
  A row whose own picture could not be taken stays empty and says so in Notes (a status bar click made while the command ran is not clicked by the replay: its row says that). A dialog that Retrace did not fill in itself (a person finished it) or that closed too soon has no filled-in picture: its row shows it as it opened and says so. When the script's rows and the recording's steps do not agree for a step (a different row count, a recorded dialog that is not a dialog row of the sheet), only that step's last row is told: it gets the last end picture there is. When steps.md has a different number of steps than the recording (hand-edited, or from an older version) no row can be told from another: each picture stays on its step's own row, as before, and the Info sheet says so. Pictures of the dialog moments are `step-NN-open.png` and `step-NN-filled.png`; a test that ended on a step has `step-NN-failed.png`: on the click's row when the test ended at the click or while its dialog was still to open (the replayer names the click, not the dialog, then), on the dialog's row when it ended on the dialog step, on the last row of a command step that has no dialog. A test that ends early (error, stop for a person) gets a picture of what AutoCAD showed then as the picture of the step that was being run; a Stop pressed by a person takes none.
- **Result** per step: Pass when all its replay steps ran, Fail when one failed, timed out or ended the run with an error (or a checkpoint of it failed), Blocked when the replay needed a person there or hit a security prompt, Not run when the replay never got to it, was stopped by a person there, or a checkpoint of it had no verdict. The sub-rows (`2.1`) of a step carry its result. A step the replay has no step of (a drawing switch) takes the result of the step before it when the replay ran to the end. **Notes**: the failure message (a checkpoint: its differences), the block, "Checkpoint not verified." and, for a step where the replay waited for a person at a dialog, "A person finished a dialog here". Messages are shortened to 400 characters. What is scrubbed: in every message that reaches the workbook (Notes, checkpoint differences, the end check line, the verdict message) a path that starts with a drive letter and `Users\<name>` (backslashes or forward slashes) is written as `%USERPROFILE%`. Nothing else is changed: a path on another drive or a network share is written as it is. The Info sheet's "Test folder" line is the folder's name only, in steps.xlsx and in an evidence workbook alike (the default root folder has the product's name in its path). The messages themselves are worded without the product's name or its command names at their sources (the replay says "the replay"; a path under the tests folder is printed from the test folder's name on, any other path as it is); `DocText.Guard` only logs a line if one slips through, and never rewrites text, so a layer, a palette or a command that a person named with the word reaches the notes unchanged.
- **Overall** never reads Pass unless the replay's verdict is PASS: a failed end check (basic check) makes the last step Fail with the differences in its Notes; a run that completed but verified nothing (verdict INCOMPLETE) leaves the last step Not run with the note "Replay ran every step; nothing verified the result (verdict INCOMPLETE): a person must check", so Overall shows In progress.
- Tester reads `Automated run`, Date is the day. The Info sheet has a line `Run` ("Automated run on AutoCAD <version>, <date and time>. Nobody clicked anything ...": when a dialog had to be finished by a person it says so instead) and the verdict and message of the replay. No user name and no computer name is written.
- Pictures are in `<test folder>\evidence\auto_<yyyyMMdd-HHmmss>\step-NN.png` (NN = the replay's step), apart from a person's.
- How a replay step is matched to a sheet step: both have the time of their first event in the recording; a replay step belongs to the last numbered step of the script that began at or before it (a dialog a command opened belongs to the command). If the script and the recording disagree on the number of steps the Info sheet says so.

Cost of the pictures: each one is taken on AutoCAD's UI thread, which is blocked for the hide wait (450 ms; 200 ms was too short, the replay window's fade-out was still in the picture; the wait is skipped when no window of Retrace's own was visible to hide, which in a normal run is never the case). Compared with the first version of this feature (200 ms) every step takes about 250 ms longer and every dialog about 1.8 s (500 ms for the dialog to be drawn, 450 ms hide wait, 400 ms before the filled-in picture, 450 ms hide wait); a 300-step test takes about 75 s longer. Measured on the test machine: the "open" and "filled" pictures of one dialog were logged 1.3 s apart.

While a command's dialog is open the pictures leave the Guide palette alone unless it floats over the dialog, and give the dialog the foreground back after the replay window and Retrace's other windows are shown again. The extra picture moments (dialog open, dialog filled in) exist only in a run for evidence: the dialog filler is asked, as in a Tdoc run, to hold the closing click until the picture is taken. A suite or Tdoc run never takes evidence pictures: each of those has its own timing (a step timeout, picture points), and a picture per step would change what they do. Replay one test at a time for evidence. No other replay changes: without the evidence request the replayer holds no capture and none of the hooks does anything.

## Limits

- Not tested in real Excel (only the OpenXML structure is checked in the unit tests, and the sheets were opened on the test machine without Excel).
- The camera captures the screen, so another program's window over AutoCAD would be in the picture; the replay brings AutoCAD to the front before each picture.
- An automated run's pictures are as accurate as the replay is: a dialog that Retrace could not fill in stops the run for a person (Blocked).
